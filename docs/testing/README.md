# Тестване

## Команди

```bash
npm run test:unit            # Vitest – чисти модули (без база)
npm run test:integration     # Vitest – домейн слой + HTTP E2E срещу gce_test (изисква `npm run build` и `npm run db:start`)
npm test                     # всичко
npm run test:econ            # икономическа симулация с ботове: node apps/worker/dist/econ-sim.js [дни]
EXTRA_CITIES=36 node apps/worker/dist/econ-sim.js 40      # мащабен тест на тика
node scripts/load-test.mjs http://localhost:3100 40 20    # натоварване (API с LOAD_TEST_DISABLE_THROTTLE=true, извън production)
npm run lint && npm run format:check && npm run typecheck
```

Интеграционните тестове и econ-sim **отказват** да работят с база, чието име не съдържа `test` (защита от изтриване на реални данни).

### Unit (`packages/*/src/*.test.ts`)

- Трудов пазар: запазване на хората, без "качване" на квалификация, посока и граници на заплатите.
- Финанси: анюитет, рейтинг, лихва и лимит, централна банка, данъци в цели центове.
- Пазар: ценово-времеви приоритет, цена на maker, без самотърговия, санкции, посока и граници на цените, базовите цени като равновесие, пренасяне на себестойността, транспорт.
- Производство: без продукция без суровини, точна консумация, ограничения от персонал/суровини/склад, технологии по сектор, енергийни мощности.
- Свят: възпроизводимост по seed, разнообразие на терена и ресурси, океански ръбове, чанкове, правила за разполагане; календар; валидиране на входни данни.
- Градска симулация: детерминизъм, растеж при инфраструктура, **без растеж без ток/вода** (този тест откри реален дефект – поправен), данъчна еластичност, **обобщена = подробна симулация** (идентично състояние и сума на потоците), цели неотрицателни парични потоци.

### Integration (`tests/integration/core|economy|backup.test.ts`)

- Регистрация/вход/грешна парола/дубликат, хеширане, сесии, възстановяване на парола (анулира сесиите, кодът е еднократен).
- Основаване на град, строителство, таксуване = регистър; идемпотентен ключ при **паралелно** двойно изпращане; строеж извън територията/в чужд град/чужди политики (403).
- **Паралелна покупка на един парцел** – само една успява.
- Предприятия: място, дублирана плочка, чужда компания (403).
- **Търговия между двама играчи**: резервиране, ескроу, такса, доставка, недублиране на доставката.
- **5 едновременни купувачи за 10 единици** – продадени точно 10.
- Недостиг на средства/стока, търговия от чужда компания, отмяна с връщане на ескроу.
- Акции и придобиване на контрол; договор: изпълнение, неустойка; кредит: вноска, идемпотентност на падежа, просрочие, неизпълнение, преструктуриране (еднократно).
- Корпоративно управление: миноритарът не може сам; гласуване → дивидент; роли (мениджър търгува, но не тегли кредит).
- **Повторно изпълнение на тик (симулиран срив)** – без нови записи в регистъра.
- **Резервно копие → промени → възстановяване** – идентично състояние, инварианти, синхронизирани броячи.
- След всеки икономически тест: проверка на инвариантите (сума на балансите 0, баланси = регистър, ескроу = поръчки, пари само от разрешени операции, неотрицателни наличности, акции в обращение = общ брой, цени в граници).

### E2E (`tests/integration/e2e.test.ts`) – стъпки 1–13 от спецификацията

Стартира компилирания API като отделен процес и минава през HTTP: регистрация и вход → начална територия и капитал (поверителност за чужд играч) → път (идемпотентен) → жилищна и индустриална зона → ТЕЦ и помпа → компания и ферма → 25 игрови дни → сгради, население, заети, произведено зърно → продажба и покупка между двама играчи → кредит за града (и отказ за чужд) → WebSocket събитие за тик → изход, 12 дни „офлайн“ (обобщена симулация), **рестарт на API процеса**, вход → прогресът е запазен и симулацията е продължила → rate limit (429), 404, невалиден инструмент (400).

## Икономическа симулация с ботове

`apps/worker/src/econ-sim.ts` – 4 бота (ферми + хранителен завод; мина + ТЕЦ; стоманолеярна; само град) с поръчки на всеки 5 дни. Резултат за 120 дни (последно изпълнение):

- Население ~2 100, БВП ~309 €/ден, ценови индекс 1,014 → 0,999; базова лихва 5% → 7,3% → 0,5% (реагира на движението на цените).
- Сделки: 71 продажби на дребно (5 606 ед.), 3 вноса.
- Всички 7 инварианта: ✔.
- Наблюдения: при 36 ферми (мащабен тест) зърното падна от 4,00 на 1,58 € – свръхпроизводството сваля цената, както се очаква; безработицата в градовете на ботовете е 16–19%, защото шаблонът не добавя нови зони (играч би реагирал).

## Натоварване

Лаптоп, всичко на една машина (API + worker + PostgreSQL), без rate limit, 40 постоянно активни виртуални потребители (без пауза между заявките), смес четене/запис, 20 s:

| Показател                      | Стойност          |
| ------------------------------ | ----------------- |
| Пропускателна способност       | 315 заявки/s      |
| Латентност p50 / p95 / p99     | 92 / 360 / 689 ms |
| Грешки 5xx                     | 0                 |
| Строителство (запис) p50 / p95 | 283 / 802 ms      |

С включен rate limit от един IP: 850 заявки/s обработени, от които 89% връщат 429 – ограничаването работи.

**Тик на симулацията:** 2 града ~150 ms; 4 града с 5 предприятия ~550 ms; **40 града + 39 компании ~5,3 s** (последователно). При интервал 20 s това е запас за ~100–150 активни града; над това – мерките от docs/architecture (шардиране на `system:world`, паралелни региони).

Целевата група за алфата (десетки играчи, ~1 заявка/s на играч) е далеч под измерения капацитет.

## Ръчна проверка в браузъра

Проверено във вградения браузър (Vite dev сървър): регистрация, основаване на град с кирилско име, придвижване/мащабиране, път с влачене, жилищна и индустриална зона, ТЕЦ и помпа, появяване на сгради при следващите тикове, панели. Проверен и мобилен изглед (виж STATUS).

## Какво не е автоматизирано

- UI тестове в браузър (Playwright) – предвидени за следващ етап; функционалността е покрита от HTTP E2E и ръчна проверка.
- Тест на прекъсване на WebSocket с повторно свързване (клиентът разчита на автоматичното повторно свързване на socket.io; ръчно не е проверено).
